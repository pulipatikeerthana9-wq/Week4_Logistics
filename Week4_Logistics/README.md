# Week 4 — Predictive Modeling and Optimization in Logistics

All records and operational results are **hypothetical simulations**. This is NEW Week 4 modeling/optimization code. The Week 3 generator is reused unchanged; earlier folders are not modified.

## Run in VS Code on Windows
1. Extract the ZIP fully.
2. Open the extracted `Week4_Logistics` folder with File > Open Folder.
3. Choose Terminal > New Terminal.
4. Run:
```powershell
cmd /c RUN_WEEK4.bat
```
The launcher creates `.venv`, installs requirements, runs 21 tests, then executes the full pipeline. It pauses on success and failure. Internet is needed for first installation.

**Use 64-bit Python 3.11, 3.12 or 3.13.** These pinned libraries were tested using Python 3.13. Do not assume Python 3.14 can install the older scikit-learn pin; install Python 3.13 alongside it if necessary. The launcher searches supported versions, not your default Python. No need to uninstall other versions.

Manual alternative (Python 3.13 shown):
```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe run_week4.py
```
For Linux/macOS use Python 3.11–3.13 with `python3 -m venv .venv` and `.venv/bin/python` instead of the Windows executable.

## Important interpretation boundaries
- Predict at warehouse release, when accumulated dwell is assumed available, not initial booking.
- Target is total duration including dwell; predictions are not remaining delivery days.
- Actual delivery dates, delay/late flags, costs and promises are not prediction features.
- Training labels must be available before each validation cutoff; June never selects models.
- Simulation has programmed relationships, not real traffic/weather/seasonality.
- Optimization changes only Standard to Express, preserving original promises. It uses predicted positive-part tardiness of a point estimate, not a calibrated expected penalty or late-delivery probability.
- Allocation is an offline June batch demonstration with June shipment inputs assumed known. A real online dispatcher must handle arrival uncertainty and rolling budgets.
- Model feature substitution is not a causal estimate; performance after upgrades has not been observed or validated.
- Costs, penalty and spare capacity are arbitrary scenario assumptions, not carrier tariffs.
- No routes, driver hours, vehicle weights or road networks are optimized.
- Permutation importance is diagnostic, not causal, and correlated inputs can mask importance.
- Model metrics are unrounded raw predictions; optimization floors predicted total duration at 1 day.
- Included logs show verification in the preparation environment, NOT on your laptop. Save genuine local terminal output after running.
- Changing code/data/seed changes results; the supplied report matches default settings only.
